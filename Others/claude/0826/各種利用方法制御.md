はい。5つを分けると、管理ポイントは次の整理になります。

| 対象                        | 主な制御方法                                                       | Windows側        | ポイント                                      |
| ------------------------- | ------------------------------------------------------------ | --------------- | ----------------------------------------- |
| **【クラウド】Cowork**          | **Organization settings / Custom Role**                      | 原則なし            | Claude Codeの「server-managed settings」とは別物 |
| **【クラウド】Claude Code**     | **server-managed settings**                                  | HKLMはクラウドには届かない | クラウドを制御するならserver-managedが必要              |
| **【ローカル】アプリ Cowork**      | **Organization settings + `HKLM\...\Claude`**                | あり              | Coworkは組織設定と端末ポリシーの両方                     |
| **【ローカル】アプリ Claude Code** | **表示制御=`HKLM\...\Claude`、実行制御=Claude Code managed settings** | あり              | 2種類のHKLMを使い分ける                            |
| **【ローカル】CLI Claude Code** | **server-managed または `HKLM\...\ClaudeCode\Settings`**        | Windowsならあり     | Desktop用`HKLM\...\Claude`は基本不要            |

CoworkとClaude Codeは、同じClaude Desktop内にあっても、ポリシー名前空間と評価機構が異なります。

## 1. 【クラウド】Cowork

これは基本的に **Claude管理コンソールのOrganization settingsで制御**します。

「Claude Codeのserver-managed settings」でCoworkを制御する、という整理ではありません。

主な制御対象は例えば以下です。

* Coworkを利用できるユーザー／グループ
* `Run Cowork in the cloud`
* Automatically approve mode
* ConnectorのAlways allow
* Remote MCP / Connectorの権限
* Code executionのnetwork egress
* Web Search
* Claude in Chrome
* Skills / Plugins
* Custom Role

Coworkは組織設定だけでなく、ローカル利用時には端末側ポリシーも組み合わせる設計です。

したがって、

> **クラウドCowork = Organization settings / Custom Role が主**

です。

端末の

```text
HKLM\SOFTWARE\Policies\Claude
```

は、**クラウド上で動作するCoworkセッションそのものの強制設定にはなりません**。

---

## 2. 【クラウド】Claude Code

ここは **server-managed settings が主制御**です。

イメージは、

```text
Organization settings
  > Claude Code
  > Managed settings
```

です。

例えばClaude Codeの以下をJSONで管理します。

```json
{
  "permissions": {
    "disableBypassPermissionsMode": "disable"
  },
  "allowManagedPermissionRulesOnly": true,
  "allowManagedMcpServersOnly": true
}
```

対象となるのは、

* Read / Write / Edit / Bash等のpermissions
* Permission bypass
* Auto mode
* MCP
* Hooks
* Plugins
* Sandbox
* Web Search / Web Fetch
* モデル制限
* その他Claude Code runtime設定

です。

**クラウドClaude CodeにはWindows端末のHKLMが存在しないため、HKLMだけでは制御できません。** クラウドセッションを含める場合はserver-managed settingsを主ポリシーにする、という整理になります。

したがって、

> **クラウドClaude Code = server-managed settings**

が基本です。

---

## 3. 【ローカル】アプリ Cowork

ここは少し特殊で、

> **Organization settings + `HKLM\SOFTWARE\Policies\Claude`**

の組み合わせです。

### 端末側

```text
HKLM\SOFTWARE\Policies\Claude
```

主な値は、

```text
secureVmFeaturesEnabled
allowedWorkspaceFolders
isLocalDevMcpEnabled
isDesktopExtensionEnabled
isDesktopExtensionDirectoryEnabled
forceLoginOrgUUID
```

などです。

例えば、

```text
HKLM\SOFTWARE\Policies\Claude

secureVmFeaturesEnabled = 1
allowedWorkspaceFolders = ["C:\\ClaudeWork"]
isLocalDevMcpEnabled = 0
isDesktopExtensionEnabled = 0
```

とすれば、

* Coworkを端末上で有効化
* Workspaceを限定
* ローカルMCP禁止
* Desktop Extension禁止

といった端末固有制御ができます。

一方、

* Auto approval禁止
* Connector Always allow禁止
* Remote MCPの権限
* クラウドCowork利用可否
* 利用ユーザー
* Web Searchなどの組織機能

はOrganization settings側です。Auto modeやConnector権限はCoworkの組織設定で管理する形です。

したがって、

> **ローカルCowork = Org設定だけでもHKLMだけでも不十分**

です。

---

## 4. 【ローカル】アプリ Claude Code

ここでいう「アプリClaude Code」を **Claude Desktop内のCode画面** とすると、制御が2段階あります。

### ① Claude Desktop上にCode機能を出すか

これは、

```text
HKLM\SOFTWARE\Policies\Claude
```

の

```text
isClaudeCodeForDesktopEnabled
```

です。

例えば、

```text
isClaudeCodeForDesktopEnabled = 0
```

なら、Desktop内Claude Codeを禁止できます。

Coworkの

```text
secureVmFeaturesEnabled
```

とは独立しているため、

```text
Cowork        ON
Desktop Code  OFF
```

も可能です。

### ② 起動したClaude Codeの動作を制御する

こちらは別で、

```text
HKLM\SOFTWARE\Policies\ClaudeCode
    Settings
```

または

```text
server-managed settings
```

です。

つまり、

```text
HKLM\SOFTWARE\Policies\Claude
```

と

```text
HKLM\SOFTWARE\Policies\ClaudeCode
```

は用途が異なります。

前者：

```text
Claude Desktop / Cowork / Code機能表示
```

後者：

```text
Claude Code runtimeのpermissions / MCP / Hooks / Sandbox等
```

です。

したがってローカルアプリClaude Codeは、

```text
機能ゲート
  HKLM\SOFTWARE\Policies\Claude
    isClaudeCodeForDesktopEnabled

実行ポリシー
  server-managed settings
       または
  HKLM\SOFTWARE\Policies\ClaudeCode\Settings
```

という構成です。

---

## 5. 【ローカル】CLI Claude Code

Claude Code CLIそのものには、基本的に

```text
HKLM\SOFTWARE\Policies\Claude
```

は関係ありません。

こちらは **Claude Code managed settings** で制御します。

Windows CLIなら、

```text
HKLM\SOFTWARE\Policies\ClaudeCode
  Settings = "{ ...JSON... }"
```

が端末管理用です。

例えば、

```json
{
  "permissions": {
    "disableBypassPermissionsMode": "disable"
  },
  "allowManagedPermissionRulesOnly": true,
  "allowManagedMcpServersOnly": true,
  "allowedMcpServers": []
}
```

です。

同じClaude Code端末ポリシーはCLIだけでなく、Desktop内Claude CodeやIDEから起動されるClaude Codeにも適用されます。

したがって、

> **ローカルCLI Claude Code = server-managed または `HKLM\...\ClaudeCode\Settings`**

です。

---

## Claude Codeで特に重要な「優先順位」

Claude Codeについてはここがかなり重要です。

概ね、

```text
優先度 高

1. server-managed settings
2. HKLM\SOFTWARE\Policies\ClaudeCode\Settings
3. C:\Program Files\ClaudeCode\managed-settings.json
4. HKCU\SOFTWARE\Policies\ClaudeCode\Settings

優先度 低
```

となります。

しかも、

> **server-managed とHKLMが単純にマージされるわけではありません。**

例えば、

```text
server-managed:
  bypass禁止

HKLM:
  MCP禁止
  sandbox強制
```

として、

```text
結果：
  bypass禁止 + MCP禁止 + sandbox強制
```

になるとは限りません。

上位のserver-managed settingsが選択されると、下位HKLMの大部分が無視される可能性があります。

そのため、運用は次のどちらかに寄せるのが安全です。

### ローカルだけ厳格管理する場合

```text
server-managed settings
    空

HKLM\SOFTWARE\Policies\ClaudeCode\Settings
    完全なClaude Codeポリシー
```

### クラウドも含めて統一する場合

```text
server-managed settings
    完全なClaude Codeポリシー

HKLM\SOFTWARE\Policies\ClaudeCode\Settings
    同じ完全なポリシーをフォールバックとして配置
```

という考え方です。

## 最終的な整理

一番シンプルに図にするとこうです。

```text
【クラウド】Cowork
  ↓
Organization settings
Custom Role
Cowork Permissions
Capabilities
Connectors
※Claude Code server-managed settingsではない


【クラウド】Claude Code
  ↓
server-managed settings
※HKLMは届かない


【ローカル】アプリ Cowork
  ↓
Organization settings
        ＋
HKLM\SOFTWARE\Policies\Claude


【ローカル】アプリ Claude Code
  ↓
表示・利用可否：
HKLM\SOFTWARE\Policies\Claude
  isClaudeCodeForDesktopEnabled

実際のClaude Code制御：
server-managed settings
        または
HKLM\SOFTWARE\Policies\ClaudeCode\Settings


【ローカル】CLI Claude Code
  ↓
server-managed settings
        または
HKLM\SOFTWARE\Policies\ClaudeCode\Settings

※HKLM\SOFTWARE\Policies\Claude は基本的に不要
```

なお、**WSL2上のClaude Code CLI**だけは追加で注意が必要です。通常はLinux側の管理設定を参照しますが、Windows HKLMを継承させたい場合はWindows側の管理設定に

```json
{
  "wslInheritsWindowsSettings": true
}
```

を設定する構成があります。

要するに、覚え方としては **「Cowork＝Org設定＋`Policies\Claude`、Claude Code＝server-managed / `Policies\ClaudeCode`」** が基本で、Desktop内Claude Codeだけはさらに `Policies\Claude` の機能ゲートが1枚手前にある、という整理が最も分かりやすいです。
