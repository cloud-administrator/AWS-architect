以下は、Active Directory参加済みWindows端末へCodex Elevated Sandboxを展開する本手順書の、`Implementation`フォルダー内にある全ファイルを用途別に整理したものです。
フォルダーには、実行用PowerShell 6本と、設定・入力・確認用ファイル6点が含まれます。

## 全体の実行順序

```text
1. ADの端末・利用者対応を登録
       ↓
2. OpenAI公式のCodexパッケージを取得・検証
       ↓
3. 配布用ペイロードを生成
       ↓
4. SKYSEA／ソフトウェア配布製品で対象PCへインストール
       ↓
5. GPOのSYSTEMタスクでElevated Sandboxを構成
       ↓
6. 受入テストで正常性を確認
```

## 1. 実行するPowerShellスクリプト

| 順番 | ファイル名                                  | 一言でいうと                                       | 使用場所・実行者                                                             | 使用するタイミング                                              | 主な処理・生成結果                                                                                                                                                                                                                                                                                     |
| -: | -------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
|  1 | `Set-CodexDeviceUserMapping.ps1`       | **PCと正式利用者の対応をADへ登録するスクリプト**                 | AD管理端末。AD更新権限を委任された管理者が実行                                            | 初回導入、対象者追加、PCの利用者変更時                                   | `CodexDeviceUserMap.csv`を読み込み、PCとユーザーの存在、ユーザーの有効性、`GG-Codex-Users`所属、重複、既存`managedBy`との衝突を確認します。問題がなければ、ADコンピューターの`managedBy`へ利用者のDNを登録し、結果レポートCSVを出力します。最初は必ず`-WhatIf`で実行します。                                                                                                                |
|  2 | `Get-CodexOfficialPackage.ps1`         | **承認済みCodex CLIをOpenAI公式配布元から安全に取得するスクリプト**  | インターネット接続可能なWindows管理端末。配布パッケージ担当者が実行                                | 新規導入時、およびCodex CLIのバージョン更新時。x64／Arm64ごとに実行             | 指定した固定バージョンの`release.json`、`codex-package_SHA256SUMS`、公式アーカイブを取得します。公式メタデータ、チェックサムファイル、実際のアーカイブのSHA-256を相互照合し、公式パッケージ構造と`codex.exe --version`も確認します。成功すると`CodexCLI`、`Download`、`package-verification.json`を生成します。                                                                             |
|  3 | `New-CodexDeploymentPayload.ps1`       | **対象PCへ配布する完成済みパッケージを作るスクリプト**               | Active Directoryモジュールを利用できるAD／配布管理端末                                 | 公式Codexパッケージの検証後。バージョン、CPUアーキテクチャ、`PolicyVersion`ごとに実行 | 検証済みCodexパッケージ、端末用スクリプト、`requirements.toml`を1つの配布ペイロードへまとめます。ADからドメインNetBIOS名と`GG-Codex-Users`のDNを取得し、Codex必須6ファイルと`requirements.toml`のSHA-256を設定した実値入り`CodexDeploymentConfig.psd1`を生成します。あわせて`payload-manifest.json`も生成します。                                                                  |
|  4 | `Install-CodexProvisioningPayload.ps1` | **生成済みペイロードを対象PCへ安全にインストールするスクリプト**          | 対象Windows PC。SKYSEAまたはソフトウェア配布製品から、**LocalSystem／SYSTEM相当**で実行       | GPOのプロビジョニングタスクを実行する前                                  | インストーラー自身、設定ファイル、プロビジョニングスクリプト、テストスクリプトのコード署名と署名者Thumbprintを確認します。CodexファイルのSHA-256とバージョンを確認した後、`Program Files`と`ProgramData`へ配置し、SYSTEM／Administratorsだけが書き換えられるACLへ固定します。成功すると`package-install.json`を生成します。ログオンユーザーやDomain Adminでは実行しません。                                                   |
|  5 | `Provision-CodexSandbox.ps1`           | **対象ユーザーのElevated Sandboxを実際に事前構成する中心スクリプト** | 対象Windows PC。コンピューターGPOのスケジュールタスクから、`NT AUTHORITY\SYSTEM`かつ最上位の特権で実行 | PC起動時、日次再試行時、Codex／ポリシーバージョン更新時                        | SYSTEM実行、多重実行、署名、Thumbprint、ACL、SHA-256、Codexバージョンを確認します。自端末のADコンピューターから`managedBy`を取得し、利用者が有効・期待ドメイン内・認可グループ所属であることを確認します。AD SIDと`Win32_UserProfile.SID`が一致する既存プロファイルを1件だけ選び、`codex sandbox setup --elevated --user ... --codex-home ...`を実行します。成功後は`state.json`と`provisioning.jsonl`を保存します。 |
|  6 | `Test-CodexDeployment.ps1`             | **導入結果が正しいかを変更なしで検査する受入テストスクリプト**            | 対象Windows PC。端末管理者または管理基盤から実行                                        | プロビジョニング直後、パイロット判定時、更新後、障害調査時                          | 現在の`managedBy`、対象ユーザーのSID・アカウント・DN、有効性、ドメイン、認可グループ、Windowsプロファイル、`state.json`、GPOタスクのSYSTEM／Highest設定、タスク操作、署名者、CodexファイルのSHA-256、`requirements.toml`、Codex成果物、ローカルsandboxユーザー／グループを読み取り専用で確認します。結果を`validation-report.json`へ出力し、Critical失敗がなければ終了コード0を返します。                                  |

## 2. 設定・入力・参照用ファイル

| ファイル名                                | 種類                     | 用途                                                                                                                                                                 | 編集・実行の要否                                                                                        | 重要な注意点                                                                                                                 |
| ------------------------------------ | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `CodexDeploymentConfig.psd1.example` | PowerShell設定テンプレート     | 実際に端末へ配布する`CodexDeploymentConfig.psd1`の設定構造を示す参考ファイルです。ドメイン名、認可グループDN、Codex固定バージョン、必須ファイルのSHA-256、配置先、タスク名、タイムアウト、利用者変更可否などの設定項目が含まれます。                            | **通常は直接実行しません。** 通常は`New-CodexDeploymentPayload.ps1`が実値入りの`CodexDeploymentConfig.psd1`を自動生成します。 | `<APPROVED_VERSION>`や`<64_HEX_SHA256>`が残ったexampleを、そのまま対象PCへ配布してはいけません。生成された本番用PSD1にはコード署名が必要です。                       |
| `requirements.toml`                  | Codex管理要件ファイル          | Codexで使用できる承認方式、permission profile、Windows sandbox方式などを端末側でも制限します。標準では`on-request`、`:workspace`、`:read-only`／`:workspace`のみ許可し、Windows sandboxは`elevated`だけに制限します。 | クラウド側のCodexポリシーと内容を合わせた上で、対象PCの`C:\ProgramData\OpenAI\Codex\requirements.toml`へ配布します。           | **UTF-8 BOMなし**で保存します。クラウドポリシーと矛盾させません。                                                                                |
| `CodexDeviceUserMap.csv`             | AD登録用入力CSV             | PC名と、そのPCの正式利用者の`SamAccountName`を対応付ける正本データです。`Set-CodexDeviceUserMapping.ps1`が読み込みます。                                                                             | 貸与台帳、CMDB、SKYSEA資産情報と照合して管理者が編集します。                                                             | 列は`ComputerName,SamAccountName`です。ドメイン名は付けず、ユーザー名だけを記載します。同じPCを複数行に記載せず、退職者、無効ユーザー、共有PCは含めません。                         |
| `GPO-Task-Action.txt`                | GPO設定用クイックリファレンス       | GPMCのスケジュールタスク画面で入力する、タスク名、実行ユーザー、トリガー、PowerShellパス、引数、開始フォルダー、再試行、タイムアウトなどをまとめたファイルです。                                                                            | 実行するファイルではありません。GPO設定時に表示し、画面へ転記します。                                                            | `<40_HEX_CODE_SIGNING_CERT_THUMBPRINT>`は、実際のコード署名証明書Thumbprintへ置き換えます。GPOタスクはSYSTEM／Highestとし、`--current-user`は使用しません。 |
| `README_ja.md`                       | Implementationフォルダー説明書 | 各ファイルの実行順序、採用方式、署名対象、本番前条件、パイロット条件をまとめた短い説明書です。                                                                                                                    | 実行しません。作業開始前に読みます。                                                                              | 詳細な画面操作やコマンドは`手順書.md`を正本として確認します。                                                                                      |
| `SHA256SUMS.txt`                     | 配布キットの整合性確認ファイル        | ZIP展開直後のImplementationファイルが、提出時の原本から変更されていないことをSHA-256で確認します。                                                                                                      | **コード署名を付ける前**に、管理端末で検証します。                                                                     | PowerShellスクリプトやPSD1へコード署名を付けるとファイル内容が変わるため、元のSHA-256とは一致しなくなります。署名後のファイルをこの原本ハッシュで再検証しないでください。                        |

## 3. 各スクリプトが生成する主な管理ファイル

| 生成ファイル                               | 生成元                                      | 用途                                                                             |
| ------------------------------------ | ---------------------------------------- | ------------------------------------------------------------------------------ |
| `CodexDeviceUserMapping-WhatIf.csv`  | `Set-CodexDeviceUserMapping.ps1 -WhatIf` | ADへ変更を加える前の事前確認レポートです。`Rejected`が1件でもあれば反映を中止します。                              |
| `CodexDeviceUserMapping-Applied.csv` | `Set-CodexDeviceUserMapping.ps1`         | 実際に`managedBy`へ反映した結果を記録します。                                                   |
| `package-verification.json`          | `Get-CodexOfficialPackage.ps1`           | 取得日時、Codexバージョン、CPUアーキテクチャ、公式アーカイブSHA-256、チェックサムファイルSHA-256、必須ファイルのハッシュを記録します。 |
| `CodexDeploymentConfig.psd1`         | `New-CodexDeploymentPayload.ps1`         | 対象PC側のインストール、プロビジョニング、テストで共通利用する本番設定ファイルです。生成後にコード署名します。                       |
| `payload-manifest.json`              | `New-CodexDeploymentPayload.ps1`         | 配布ペイロードのバージョン、アーキテクチャ、`PolicyVersion`、ドメイン、認可グループ、ハッシュ情報を記録します。                |
| `package-install.json`               | `Install-CodexProvisioningPayload.ps1`   | 対象PCへのファイル配置が完了したことを記録します。端末名、Codexバージョン、ポリシーバージョン、署名者Thumbprint、配置先を保持します。    |
| `provisioning.jsonl`                 | `Provision-CodexSandbox.ps1`             | プロビジョニング開始、成功、既に適合、失敗などのイベントをJSON Lines形式で記録します。パスワードやsecretの内容は記録しません。        |
| `state.json`                         | `Provision-CodexSandbox.ps1`             | そのPCで、どのADユーザー、SID、`CODEX_HOME`、Codexバージョン、ポリシーバージョンに対して構成を完了したかを記録します。        |
| `validation-report.json`             | `Test-CodexDeployment.ps1`               | 受入テストの全チェック項目、合否、Critical失敗件数を記録します。                                           |
| `config.toml`                        | Codexの` sandbox setup`処理                 | 対象ユーザーの`.codex`配下へ作成・更新され、`windows.sandbox = "elevated"`が保存されます。               |
| `setup_marker.json`                  | Codexのsandbox setup helper               | Elevated Sandboxのセットアップ完了状態を示します。                                              |
| `sandbox_users.json`                 | Codexのsandbox setup helper               | sandbox用ローカルアカウントの保護情報を保持します。**存在だけを確認し、内容を表示、収集、コピー、チケット添付しません。**             |

## 4. 作業担当ごとの使い分け

| 担当                 | 主に使用するファイル                                                                          |
| ------------------ | ----------------------------------------------------------------------------------- |
| AD管理者              | `CodexDeviceUserMap.csv`、`Set-CodexDeviceUserMapping.ps1`                           |
| 配布パッケージ担当者         | `Get-CodexOfficialPackage.ps1`、`New-CodexDeploymentPayload.ps1`、`requirements.toml` |
| SKYSEA／ソフトウェア配布担当者 | 生成済みペイロード、`Install-CodexProvisioningPayload.ps1`                                    |
| GPO管理者             | `GPO-Task-Action.txt`、`Provision-CodexSandbox.ps1`                                  |
| 端末管理者／受入担当者        | `Test-CodexDeployment.ps1`、`state.json`、`validation-report.json`                    |
| セキュリティ担当者          | `SHA256SUMS.txt`、コード署名、各種ハッシュ・ログ・受入結果                                               |

最も重要な区別は、**最初の3本は管理端末で配布物を準備するためのスクリプト、`Install-CodexProvisioningPayload.ps1`は配布製品が対象PCで実行するスクリプト、`Provision-CodexSandbox.ps1`はGPOが実行するスクリプト、`Test-CodexDeployment.ps1`は結果確認用スクリプト**という点です。
