調査基準日	2026-08-21								
設定先	https://chatgpt.com/codex/cloud/settings/policies								
対象範囲	公式Requirements Referenceに直接掲載された項目と、Requirementsが同じ構造を参照する権限プロファイル・Hooks・公開Featureスキーマを収録。 config.tomlにのみ掲載され、requirements.tomlへの入れ子適用が公式に明記されていない項目は、参考区分として分離。								
読み方／不明の扱い	設定を省略した場合は、原則としてrequirementsによる制約なしとなり、下位設定や通常の製品動作に従います。 「不明」は、公式文書で型、既定、詳細動作、またはrequirements.tomlでの適用可否を確認できなかった箇所です。推測で補っていません。								
要件の優先順位	低い順に、システムrequirements.toml → クラウド配信の管理要件 → legacy managed_config.tomlから再解釈された要件 → macOS MDMのrequirements_toml_base64。 高優先層は通常のスカラー／リスト値を上書きします。テーブルはキー単位で合成されますが、rules、hooks、ファイル制限などは項目固有の合成規則があります。								
重要なバージョン条件	allowed_permission_profiles と管理default_permissionsはCodex 0.138.0以上が必要です。0.137.0以前はこれらを無視します。 対応する要件はクライアントとバージョンで異なるため、全社配布前に実際の対象版で許可・拒否の両方を検証します。								
サンドボックス方式	権限プロファイル方式では allowed_permission_profiles と default_permissions を使用します。 従来方式では allowed_sandbox_modes を使用します。同一展開で旧sandbox設定と権限プロファイルを混在させないことが基本です。								
ネットワークの適用範囲	管理ネットワークや権限プロファイルのドメイン規則が制御するのは、ローカルのサンドボックス内コマンド通信です。 Web検索、Apps／コネクタ、MCP、ブラウザ、Computer Use、Codexサービス通信、Codex cloudは別の設定で制御します。								
Hooks／ファイル保護	管理HooksのスクリプトはCodexから配布されません。MDM等で絶対パスへ配置・更新し、改ざん防止を行います。 permissions.filesystem.deny_readはユーザーが弱められません。ただしネイティブWindowsでは直接ファイルツールに適用され、shell subprocessの読取りにはこの規則が使われない制約があります。								
導入時の保守的な出発点	承認はon-request、承認者はuserを基本とし、:read-onlyと:workspaceだけを許可して:danger-full-accessを除外。 Web検索、Apps、プラグイン、ブラウザ、Computer Useは業務要件が確認できるまで無効化。 コマンド通信は正確な許可ドメインだけに限定し、dangerously_*はfalse。秘密情報はdeny_readで保護し、Hooksは無効化または管理Hooksのみに限定します。
