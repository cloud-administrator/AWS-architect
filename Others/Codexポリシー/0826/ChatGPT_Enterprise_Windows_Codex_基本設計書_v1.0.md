# 1. 目的

本設計の目的は、ChatGPT Enterpriseを利用する企業のWindows端末において、ChatGPTデスクトップアプリ内のCodex機能を業務利用するための安全な実行基盤と管理方法の明確化。

Codexはローカルファイル、シェル、Git、開発ツール等を利用できるため、通常のチャット利用より端末への影響範囲が大きい。本設計では、最小権限、既定拒否、人間承認、外部通信経路の縮小、企業管理ポリシーの強制を基本方針とする。

利用者の利便性を確保しつつ、作業領域を原則としてユーザープロファイル配下の codex_work に限定し、共有フォルダ、他のローカル領域、外部連携機能へのアクセスを抑制する。

# 4. 全体構成

## 4.1 構成概要

本設計では、利用資格、アプリ配布、OS実行許可、企業ポリシー、Windowsサンドボックス、作業フォルダの各レイヤーを組み合わせて防御を多層化する。

| **①利用申請/Enterprise資格** | **②SKYSEA配布** | **③ChatGPT Desktop / Codex** | **④elevated sandbox**    | **⑤codex_work**          |
|------------------------------|-----------------|------------------------------|--------------------------|--------------------------|
| 対象者限定                   | 対象端末のみ    | クラウド管理requirements適用 | 低権限サンドボックス実行 | 原則唯一の書込領域       |
| AppLocker許可                | 端末配布管理    | 承認・Web・MCP・機能制御     | ネットワーク/権限制御    | .git / .codex は読取専用 |

## 4.2 制御境界

| **レイヤー** | **制御手段**                                | **役割**                                                           |
|--------------|---------------------------------------------|--------------------------------------------------------------------|
| 利用資格     | ChatGPT Enterpriseアカウント + 利用申請承認 | 未承認利用者への配布抑止                                           |
| アプリ配布   | SKYSEA                                      | 許可されたユーザー端末への配布                                     |
| アプリ実行   | AppLocker許可ルール                         | 会社端末上でのChatGPTアプリ実行                                    |
| ポリシー強制 | ChatGPT Enterprise管理コンソール            | requirements.toml互換の管理要件を利用者が上書きできない形で配信    |
| ローカル実行 | Windows elevated sandbox                    | 制限ユーザー、ファイル境界、ネットワーク遮断を利用したコマンド分離 |
| ファイル領域 | `C:\Users\<ユーザー>\codex_work`             | 業務上のCodex作業ファイルの集約                                    |

## 4.3 ポリシー適用フロー

1.  利用者がChatGPTデスクトップアプリを起動し、ChatGPT Enterpriseアカウントでサインインする。

2.  対応クライアントが、サインインIDに対応するクラウド管理requirementsを取得する。

3.  有効なキャッシュがある場合は当該ポリシーを利用し、必要に応じて更新する。

4.  有効なキャッシュがなくクラウド要件の取得にも失敗した場合、管理要件なしで継続せずエラーとする製品仕様。

5.  Codexのローカル操作は、強制されたPermission ProfileおよびWindows elevated sandboxの範囲で実行する。

## 5.2 AppLocker設計

ChatGPTデスクトップアプリに対するAppLockerの実行制限解除または許可ルール反映は、アプリ配布前の端末前提条件。AppLocker全体を無効化するのではなく、会社の既存アプリケーション制御方針に従ってChatGPTアプリを実行可能な状態とする。

本案件ではAppLocker対応済みとして扱い、ルール作成方式や署名者条件等の詳細は既存端末管理設計の管理範囲。

## 5.3 SKYSEA配布設計

ChatGPTデスクトップアプリはSKYSEAを用いて各ユーザーの端末へ配布する。配布対象は「ChatGPT Enterpriseアカウント保有」かつ「ChatGPTデスクトップ利用申請承認済み」の利用者に限定する。

無申請利用を抑止するため、アプリ配布対象リストとEnterprise利用者管理を突合し、異動・退職・利用停止時は配布対象から除外する運用。

## 5.4 Windowsサンドボックス事前プロビジョニング

Windows elevated sandboxは、初期セットアップ時に管理者権限が必要な方式。通常利用時の都度UAC要求を発生させないことを目的に、端末管理者が利用開始前に対象ユーザー単位で事前プロビジョニングする。

> 実施コマンド例は以下。ユーザー名、ドメイン名、ユーザープロファイルパスは実際の対象者に置換する。
>

```powershell
codex sandbox setup --elevated --user "testdomain\tanaka-tarou" --codex-home "C:\Users\tanaka-tarou\.codex"
```

elevatedはCodex自体へ管理者権限を付与する設定ではなく、Windows上でより強いサンドボックス実装を構成するための名称。通常のCodexプロセスは非昇格で動作させる前提。

## 5.5 ChatGPT Enterprise管理コンソール

requirements.toml互換の管理要件は、ChatGPT EnterpriseのManaged configuration画面で作成・割当する。管理画面は https://chatgpt.com/codex/cloud/settings/policies を利用する。

本設計ではクラウド管理を主たる配信方式とし、利用者がローカル設定でセキュリティ要件を緩和できない構成とする。設定変更は変更管理を経て、代表ユーザーでの事前検証後に本番割当へ反映する。

# 6. requirements.toml ポリシー設計

本章では、作成済みrequirements.tomlの設定内容を基本設計項目として整理する。TOML本文は掲載せず、設定項目、設定値、設計理由、留意事項を記載する。

## 6.1 承認・Web検索・管理機能

| **分類**       | **設定項目**                | **設定値**    | **設計理由**                                                                            | **留意事項**                                               |
|----------------|-----------------------------|---------------|-----------------------------------------------------------------------------------------|------------------------------------------------------------|
| 承認ポリシー   | allowed_approval_policies   | `[untrusted]` | Never実行を禁止し、既知の安全な読み取り以外は原則として承認を要求するため。             | 全操作を例外なく承認対象にする設定ではない。               |
| 承認者         | allowed_approvals_reviewers | `[user]`      | 自動レビューによる承認を禁止し、人間の利用者のみが承認できるようにするため。            | 利用者自身が危険操作を承認するリスクは残る。               |
| Web検索        | allowed_web_search_modes    | `[cached]`    | ライブ検索およびインデックス検索を禁止し、Web検索経路をOpenAIキャッシュに限定するため。 | disabledは仕様上常に利用可能。                             |
| Hooks          | allow_managed_hooks_only    | true          | ユーザー、プロジェクト、セッション、プラグイン由来の未管理Hooksを読み込ませないため。   | 本設定では管理Hook自体を定義しないため、現状Hook実行なし。 |
| Appshots       | allow_appshots              | false         | 画面・アプリ状態を取得する別経路を減らすため。                                          | 対応クライアントで機能を無効化。                           |
| Remote Control | allow_remote_control        | false         | Codex経由のデバイス遠隔操作を禁止するため。                                             | Codex外のSSH等を無効化する設定ではない。                   |

| WSL起動                 | wsl / wsl.exe                                                           | forbidden | WSL経由でWindowsドライブや共有領域へ迂回する経路を抑止するため。       | Codex UI上のWSL実行環境選択自体は別制約。                |
| マウント・共有・ACL変更 | mount / subst / New-PSDrive / New-SmbMapping / icacls / takeown 等      | forbidden | 共有接続、ドライブ割当、OSアクセス権変更による境界回避を抑止するため。 | PowerShell/.NET APIや独自ツールは別経路。                |
| Windows共有接続         | net use                                                                 | forbidden | Windows共有フォルダ接続・ネットワークドライブ割当を明示禁止するため。  | 主要コマンド経路の追加防御。                             |
| シェル・言語・ビルド    | PowerShell / cmd / bash / Python / Node.js / .NET / Java / Go / Rust 等 | prompt    | 任意コード実行につながる主要ツールを人間承認対象とするため。           | 未列挙実行ファイル、ラッパー等は一致しない可能性。       |
| Git・検索・転送         | git / rg / find / curl / wget / ssh / robocopy / tar / 7z 等            | prompt    | ファイル参照・検索・転送・リポジトリ操作を人間承認の対象とするため。   | 組み込みツールや別実装まで例外なく承認対象にはできない。 |

## 6.6 Windowsサンドボックス

| **設定項目**                            | **設定値**   | **設計理由**                                                                            | **補足**                                                                                                                      |
|-----------------------------------------|--------------|-----------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------|
| windows.allowed_sandbox_implementations | `[elevated]` | より強いWindowsサンドボックスのみを許可し、unelevatedへのフォールバックを禁止するため。 | elevatedはCodexへの管理者権限付与ではなく、専用低権限ユーザー、ファイル境界、ファイアウォール等を利用するサンドボックス実装。 |

# 7. 利用者・アクセス管理設計

## 7.1 利用許可条件

ChatGPTデスクトップアプリの利用者は、次の2条件を両方満たす者に限定する。

- ChatGPT Enterpriseワークスペースのアカウントを保有していること。

- ChatGPTデスクトップアプリの利用申請が承認されていること。

アプリの存在だけで利用を許可したと判断せず、Enterprise資格と社内申請の両方を管理上の許可条件とする。

## 7.2 配布・停止

| **イベント** | **設計**                                                                                          |
|--------------|---------------------------------------------------------------------------------------------------|
| 新規利用     | 申請承認後、対象者の端末へSKYSEA配布。必要に応じてcodex_work作成とサンドボックス事前設定を実施。  |
| 異動         | 所属・職務変更により利用要件がなくなった場合、配布対象・Enterprise権限を見直す。                  |
| 利用停止     | SKYSEAの配布対象から除外し、必要に応じてアプリ削除。Enterprise側の利用権限も別途停止。            |
| 端末交換     | 新端末でAppLocker、codex_work、サンドボックスプロビジョニング、アプリ配布、ポリシー適用を再確認。 |

# 8. セキュリティ設計

## 8.1 セキュリティ方針

| **方針**     | **設計**                                                                               |
|--------------|----------------------------------------------------------------------------------------|
| 最小権限     | Codexの書込先をcodex_workへ限定し、全体は既定拒否。                                    |
| 既定拒否     | ファイルシステム、Permission Profile、MCP、外部連携をAllowlist型で管理。               |
| 人間承認     | 自動承認を禁止し、主要な実行・検索・転送操作を利用者承認対象。                         |
| 通信経路縮小 | ローカルコマンド通信を無効化し、Web検索はcachedのみ。Apps、MCP、ブラウザー等を無効化。 |
| 権限昇格抑止 | 主要な昇格コマンドを禁止し、通常利用は非管理者プロセスを前提。                         |
| 多層防御     | requirements.tomlだけに依存せず、AppLocker、SKYSEA、利用申請、Windows sandboxを併用。  |

## 8.2 脅威と対策の対応

| **脅威**                              | **対策**                                                             | **主な制御レイヤー**                     |
|---------------------------------------|----------------------------------------------------------------------|------------------------------------------|
| 業務外ファイルの閲覧・改変            | root deny、codex_workのみwrite、共有領域も既定拒否                   | requirements.toml                        |
| 外部送信・データ持出し                | ローカルコマンドnetwork=false、live Web禁止、Apps/MCP/ブラウザー無効 | requirements.toml                        |
| 未承認コード実行                      | untrusted、人間承認、主要シェル/開発ツールprompt                     | requirements.toml                        |
| 権限昇格による境界回避                | runas等の主要昇格コマンドforbidden、通常利用非管理者                 | requirements.toml + 端末運用             |
| WSL/共有経由の迂回                    | wsl禁止、/mnt等deny_read、net use等禁止                              | requirements.toml                        |
| ポリシーのユーザー変更                | クラウド管理requirements、.codex read-only                           | Enterprise管理 + requirements.toml       |
| 未承認利用者の利用                    | Enterprise資格 + 申請承認 + SKYSEA配布対象管理                       | 運用統制                                 |
| 弱いWindows sandboxへのフォールバック | allowed_sandbox_implementations=`[elevated]`                         | requirements.toml + 事前プロビジョニング |

## 8.3 作業データの扱い

Codexへ投入する業務ファイルは原則として codex_work 配下に配置する。共有フォルダや他のユーザーフォルダをWorkspaceとして選択しても、管理Permission Profileでは権限を付与しない。

codex_workをネットワーク共有、フォルダリダイレクト、ジャンクション、シンボリックリンク等で別媒体へ転送する構成は避ける。requirements.tomlだけでは物理配置を検証できないため、端末準備時の確認項目とする。

# 9. 運用・変更管理設計

## 9.1 ポリシー変更管理

| **工程** | **設計**                                                                                     |
|----------|----------------------------------------------------------------------------------------------|
| 変更起票 | 設定変更理由、対象ユーザー、影響機能、ロールバック方針を記録する。                           |
| レビュー | セキュリティ担当および運用担当で、ファイル・ネットワーク・承認・外部連携への影響を確認する。 |
| 事前検証 | 代表端末・代表ユーザーへ先行割当し、許可操作と禁止操作を両方確認する。                       |
| 本番反映 | ChatGPT Enterprise管理コンソールで対象へ割当する。                                           |
| 事後確認 | ポリシー反映後、実効設定と主要テスト結果を確認する。                                         |
| 記録     | 変更日、版数、承認者、検証結果を構成管理台帳に記録する。                                     |

## 9.2 クライアントバージョン管理

Permission Profileの管理強制を利用するため、Codex 0.138.0以降の対応ランタイムを配布条件とする。0.137.0以前はallowed_permission_profilesおよびmanaged default permissionの強制を解釈しないため、本番利用対象外。

ChatGPTデスクトップアプリの更新時は、requirements.tomlで使用しているキーの対応状況とWindows elevated sandboxの動作を代表端末で確認してから展開する。

## 9.3 障害時の扱い

| **事象**                 | **基本対応**                                                                                                                                         |
|--------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------|
| クラウドポリシー取得失敗 | 有効なポリシーキャッシュがある場合は既存要件で起動。キャッシュがなく取得にも失敗した場合はポリシーなし起動を許容せず、利用を中止して運用窓口へ連絡。 |
| elevated sandbox不全     | Codex利用を継続せず、プロビジョニング状態と対象ユーザー、.codexパス、クライアント版を確認。unelevatedへ切り替えて回避しない。                        |
| codex_workアクセス不可   | フォルダ存在、所有者、ACL、リダイレクト有無を確認。別Workspaceへ広く権限付与して回避しない。                                                         |
| 業務ツール動作不可       | tmpdir denyや.git read-only等の影響を確認し、ポリシー緩和が必要な場合は変更管理を経る。                                                              |
